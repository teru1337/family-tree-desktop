# Прототип интерфейса — этап 7

Интерактивный desktop-прототип выбранного направления «Тихий семейный альбом».

## Что можно проверить

- выбрать человека на дереве;
- открыть карточку и изменить сведения;
- добавить человека или родственника;
- выбрать тип связи: родитель, ребёнок, брат/сестра, супруг или партнёр;
- указать точность даты;
- увидеть все записи проекта на общем полотне дерева;
- перемещать полотно стрелками или перетаскиванием;
- изменить масштаб дерева;
- включать и выключать фотографии на карточках;
- выбрать визуальный стиль дерева;
- добавить связь с существующим человеком;
- указать биологическое родство или усыновление;
- указать опекунство, неизвестный тип связи, неполнородное или сводное родство;
- добавить брак или партнёрство;
- отметить развод с необязательной датой;
- найти человека по имени или месту;
- отфильтровать поиск по поколению, типу связи, годам рождения и месту рождения;
- показать всё дерево, центрировать полотно или вернуться к выбранному человеку;
- увеличить или уменьшить масштаб дерева;
- открыть проект из файла `.familytree`;
- сохранить проект в файл `.familytree`;
- подготовить отдельную копию проекта;
- увидеть автоматические копии и восстановить одну из них;
- открыть меню экспорта и печати.
- создать PNG для семейного альбома;
- создать TIFF для типографии;
- создать PDF-плакат на одном большом листе;
- разбить дерево на страницы A4, A3 или A2 в книжной или альбомной ориентации;
- выбрать качество «Экран», «Печать» или «Плакат»;
- получить размер изображения и число листов до создания файла;
- увидеть предпросмотр всей компоновки перед созданием PNG, TIFF или PDF;
- отменить или повторить последнее изменение кнопками в верхней панели;
- использовать Ctrl+Z, Ctrl+Y или Ctrl+Shift+Z для управления историей действий;
- новое дерево начинается пустым, без демонстрационных родственников;
- открыть тестовый набор из 37 записей и 9 семейных событий;
- найти человека без ФИО и даты рождения;
- изменить неполные сведения, сохранив приблизительную дату;
- добавить новую запись с минимальными данными;
- сохранить запись и сразу перейти к добавлению следующего родственника;
- проверить усыновление и развод с датой;
- увидеть 10 автоматических копий и восстановить предыдущую версию;
- перезапустить прототип и убедиться, что рабочая копия восстановилась.

## Оптимизация больших деревьев

- общий расчёт расположения дерева передаётся между полотном и нижней строкой состояния без повторного вычисления;
- связи используют индекс людей по ID, поэтому не перебирают весь список при построении каждой линии;
- карточки и линии за пределами видимой области полотна временно не добавляются в DOM, а небольшой запас по краям сохраняет плавность панорамирования;
- изменение размера рабочей области отслеживается через `ResizeObserver`, поэтому область отрисовки обновляется и при закрытии правой панели.

## Рабочее хранение — этап 3

- рабочая копия сохраняется локально в браузере после изменения данных;
- автоматические копии создаются с небольшой задержкой после сохранения записи;
- хранится до 10 последних копий;
- файл проекта имеет JSON-структуру с расширением `.familytree` и версией формата;
- файлы формата v1–v5 автоматически мигрируют в v6 без удаления исходных пользовательских данных;
- даты рождения хранятся структурировано: точный день, год, приблизительная дата, диапазон или неизвестно;
- для записи сохраняются источник сведений, уровень достоверности и явный признак «неизвестный человек»;
- при проверке проекта приложение предупреждает о возможных дубликатах, циклических родительских связях, невозможной хронологии и слишком маленьком возрасте для родительства или отношений;
- в сохранённом файле связи хранятся в одной таблице `relations`: родительство, братско-сестринские связи и партнёрства не дублируются в карточках людей;
- фотографии, добавленные через карточку человека, сохраняются в разделе `photos` внутри файла проекта;
- для встроенных фотографий сохраняются MIME-тип, размер и контрольная сумма; внешние пути отмечаются предупреждением;
- перед записью создаётся временная копия, а при сбое приложение проверяет предыдущую рабочую копию;
- при открытии проверяются идентификаторы людей и ссылки на связи; исправимые замечания не блокируют загрузку;
- кнопка «Открыть проект» загружает файл с компьютера;
- кнопка «Сохранить проект» скачивает файл в выбранную папку браузера;
- в меню «⋯» доступны скачивание и восстановление резервных копий.

## Единая таблица связей — текущий блок

- родительская связь хранит `parentId`, `childId`, тип и собственный ID;
- связь братьев и сестёр хранит два ID участников, тип (`biological`, `half`, `step` или `unknown`) и собственный ID;
- супружеская или партнёрская связь хранит два ID участников, тип, статус и даты;
- массивы `parentIds`, `parentLinks`, `partnerIds`, `childIds` и `partnerships` используются только как совместимое представление внутри старого интерфейса и не записываются в новый файл;
- при открытии старого проекта интерфейс получает такое же представление, поэтому существующие `.familytree` не ломаются.

## Редактирование дерева — этап 4

- «Управлять связями» связывает выбранного человека с существующей записью;
- родительство можно отметить как биологическое или усыновительское;
- браки и партнёрства хранятся отдельными событиями;
- развод завершает связь, но сохраняет её в истории;
- даты людей и семейных событий можно оставить пустыми или указать как приблизительные.

## Запуск в режиме разработки

Из этой папки:

```text
npm run dev -- --host 0.0.0.0 --port 4173 --strictPort
```

Прототип предназначен для проверки интерфейса, рабочего хранения, экспорта и большого
тестового дерева.

## Сборка установщика Windows

Из этой папки выполните:

```text
npm install
npm run dist:win
```

Готовый установщик появится в `release/FamilyTree-Setup-0.2.0.exe`. Он устанавливает
приложение для Windows 10/11 x64, создаёт ярлыки и добавляет стандартное удаление
через настройки Windows. Проекты `.familytree` не включаются в установщик и должны
храниться отдельно как пользовательские данные.

## Релизы и обновления

Релиз публикуется автоматически после отправки тега вида `v0.2.0`. Инструкция
находится в `../docs/17-releases-and-updates.md`. Установленное приложение
проверяет GitHub Releases при запуске и предлагает скачать новую версию.
