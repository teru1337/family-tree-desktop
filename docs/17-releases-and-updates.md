# Этап 17 — релизы и автоматические обновления

Текущий опубликованный релиз: **v0.3.5**. Для корректной работы встроенного
updater в каждом Windows-релизе должны присутствовать установщик, его `.blockmap`
и `latest.yml`.

## Что добавлено

- приложение проверяет новую версию при запуске установленной Windows-сборки;
- в меню «•••» добавлена ручная проверка обновлений;
- при наличии новой версии показывается окно с текущей и новой версиями;
- обновление можно скачать, открыть страницу релиза или установить после перезапуска;
- GitHub Releases настроен как источник обновлений;
- GitHub Actions собирает и публикует Windows-релиз после отправки тега v*.

## Как выпустить новую версию

В каталоге prototype увеличьте версию в package.json и package-lock.json.
Удобнее выполнить:

~~~powershell
npm version patch --no-git-tag-version
~~~

Затем отправьте изменения и тег:

~~~powershell
git add prototype/package.json prototype/package-lock.json
git commit -m "Release v0.1.1"
git tag v0.1.1
git push origin main
git push origin v0.1.1
~~~

GitHub Actions автоматически соберёт FamilyTree-Setup-0.1.1.exe,
latest.yml и файл контрольных блоков, после чего опубликует их на странице
релиза.

## Как выглядит страница релиза

Открыть её можно по адресу:

<https://github.com/teru1337/family-tree-desktop/releases>

Для обычного релиза должны быть выполнены условия:

- релиз опубликован, а не сохранён как Draft;
- тег имеет вид v0.1.1;
- релиз не отмечен как Pre-release;
- среди файлов есть установщик и latest.yml.

## Важные ограничения

- сейчас публикуется только Windows x64;
- обновление работает для приложения, установленного через NSIS;
- текущий установщик не подписан сертификатом, поэтому проверка подписи
  обновления временно отключена и Windows может показать предупреждение
  SmartScreen;
- пользовательские файлы .familytree не передаются в GitHub и не заменяются
  обновлением.
