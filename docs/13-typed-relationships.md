# Этап 13 — типизированные связи и идентификаторы

## Что добавлено

- У каждого человека сохраняется стабильный `id`.
- У каждой связи родитель–ребёнок появляется `id` вида `parent-link-...`.
- Связь родитель–ребёнок имеет тип `biological`, `adoptive` или `step`.
- Партнёрство имеет самостоятельный `id`, тип `marriage` или `partnership`, статус и даты.
- Повторяющиеся ID партнёрств при загрузке не ломают проект: второму ID добавляется суффикс.
- Старые проекты с одними `parentIds` автоматически получают биологические связи с ID.
- В `schemas/schema-v1.sql` добавлено необязательное поле пола и представление
  `relationship_index`, которое показывает каждую связь с обеих сторон.

## Правая панель

Для выбранного человека отображаются:

- семейный статус: «В браке», «В партнёрстве», «Разведён(а)» или «Не указан»;
- родители, супруги и дети;
- роль связанного человека и обратная роль, например «Отчим · вы для него: пасынок»;
- ID каждой связи;
- ID самого человека и полный список его связей.

Если пол не указан, используются нейтральные варианты «Отчим/мачеха» и
«Пасынок/падчерица».

## Добавление человека

При создании записи можно выбрать:

- без связи;
- родителя или ребёнка с типом «Биологическая», «Усыновление» или «Степ-родство»;
- супруга/супругу с типом «Брак» или «Партнёрство».

Пол человека остаётся необязательным и используется только для более точной
подписи ролей. В редакторе существующей записи его также можно указать позже.

## Совместимость

Существующие проекты этапов 2–12 продолжают открываться. Недостающие типы и ID
связей достраиваются при нормализации данных и сохраняются при следующем экспорте.
