# Этап 65 — P0.2: безопасное быстрое сохранение

## Цель

После открытия или первого сохранения проекта повторно сохранять его в тот же
файл через `Ctrl+S`, не повреждая предыдущую рабочую версию при сбое записи.

## Что изменено

- В Electron добавлено нативное открытие `.familytree` с передачей в renderer
  полного пути, имени и содержимого файла.
- Путь открытого или впервые сохранённого проекта хранится в состоянии текущего
  сеанса и не записывается внутрь пользовательского формата.
- `Ctrl+S` вызывает обычное сохранение проекта; повторные нажатия во время уже
  идущей операции не создают параллельные записи.
- Перед заменой существующего файла его содержимое копируется в боковую копию
  `<имя-файла>.backup`.
- Новый файл сначала записывается во временный файл, перечитывается для проверки,
  затем переносится на целевой путь.
- Если старый путь недоступен, приложение не теряет текущие изменения и открывает
  нативный сценарий выбора нового места.
- Поведение «Сохранить копию» и архива материалов не менялось по смыслу.

## Совместимость и безопасность

Версия формата `.familytree` не изменялась. `Win+S` намеренно не перехватывается:
в Windows это системное сочетание поиска; для приложения используется безопасный
`Ctrl+S`. При ошибке до замены основного файла старый файл остаётся на месте.

## Проверка

- проверена атомарная запись нового файла;
- проверена боковая копия предыдущей версии;
- проверено, что ошибка создания копии оставляет основной файл неизменным;
- проверены native open, `Ctrl+S`, недоступный путь и fallback в «Сохранить как».

Полный `npm test` и production-сборка выполняются перед commit этапа.
