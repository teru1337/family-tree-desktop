# Stage 83 M2 — плавное добавление родственников

Дата: 26.08.2026  
Статус: завершён 26.08.2026.

## Что сделано

- Добавлена единая прерываемая последовательность `prepare → reveal → settle`
  для добавления человека после успешной канонической операции.
- Одна и та же последовательность используется для родителя, ребёнка,
  супруга/партнёра, брата/сестры и вариантов с неизвестным типом связи.
- Новая карточка получает entrance M1, исходная карточка — мягкую подсветку,
  а изменённая родительская или партнёрская линия — отдельный motion-сигнал.
  Для брата/сестры временно строится connector-overlay между двумя карточками;
  каноническая постоянная геометрия дерева при этом не меняется.
- Успешное добавление сначала фиксирует `nextGraph`, затем запускает motion;
  при исключении до `setPeople` данные и предыдущая сцена остаются без изменений.
- Отмена формы не вызывает операцию и не запускает motion. Повторное добавление
  отменяет старые `requestAnimationFrame` и таймеры, не позволяя устаревшей сцене
  изменить toast или снять новую подсветку.
- Результат объявляется существующим `role=status`/`aria-live` toast после
  завершения последовательности; в reduced-motion режим результат объявляется
  сразу, без промежуточных переходов.

## Pixso MCP и визуальная база

Локальный Pixso MCP доступен и проверен. В текущем Pixso-файле нет
верхнеуровневого reference frame, поэтому M2 не записывает внешний макет и не
передаёт туда семейные данные. Проверка опирается на текущий renderer, motion
tokens M0 и обезличенные сценарии отношений.

- Stage 81–83 motion tests: 8/8 пройдены.
- `npm test`: 205/205 тестов пройдены.
- `npm run build:renderer`: пройден; основной renderer bundle — 499 980 байт

- `npm run dist:win`: renderer-часть и bundle gate пройдены; локальный

  Electron runtime-каталога, поэтому итоговую упаковку M2 дополнительно
  подтверждает GitHub Actions после push/tag.
- Визуальная проверка текущего renderer в Chromium на Windows при 1920×1080:
  стартовое меню, модальное окно и декоративный фон не обрезаются; постоянная
  геометрия дерева не меняется ради motion.
- Сценарии Stage 48 подтверждают сохранение и повторное открытие родительских,
  партнёрских и sibling-связей без изменения формата `.familytree`.

## Остаточный риск

Полный ручной сценарий с живым вводом формы и покадровой проверкой всех четырёх
типов связи остаётся частью Windows smoke-проверок следующего цикла. M3 должен
подключить тот же координатор к раскрытию и сворачиванию ветвей, не смешивая
канонические данные с визуальным состоянием collapse.
