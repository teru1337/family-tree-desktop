# Этап 3. Рабочее хранение

## Цель

Дать пользователю безопасный локальный сценарий: изменить данные, сохранить рабочую
копию, выгрузить файл проекта, открыть его позже и восстановиться после ошибки.

## Формат файла проекта

Расширение прототипа — `.familytree`. Внутри используется JSON со следующими разделами:

- `manifest` — формат, версия и даты создания/изменения;
- `project` — идентификатор, название и имя файла;
- `people` — профильные данные людей без дублирующих ссылок на родство;
- `relations` — единая таблица родительских и партнёрских связей с ID участников;
- `photos` — фотографии людей, встроенные в файл проекта, с MIME-типом, размером и контрольной суммой;
- совместимые поля старого формата используются только при миграции и не записываются обратно.

Версия формата сейчас равна `4`. В сохранённом JSON связи находятся в едином разделе
`relations`, а не дублируются в каждой записи человека и в отдельном списке партнёрств.
При открытии проверяются формат, версия, наличие списка людей, уникальность
идентификаторов и корректность участников связей. Повреждённый или неподдерживаемый
файл не заменяет текущие данные.

Для совместимости с прототипом версии 3 и более ранними файлами автоматически собираются
родительские связи из `parentIds`, `parentLinks`, `childIds`, а партнёрские — из
`partnerIds` и `partnerships`. После миграции сохраняется только каноническая таблица:

```json
{
  "relations": [
    { "id": "parent-link-child-parent-biological", "kind": "parent", "parentId": "parent", "childId": "child", "type": "biological" },
    { "id": "partnership-1", "kind": "partnership", "personIds": ["parent", "partner"], "type": "marriage", "status": "active" }
  ]
}
```

Дата рождения человека в v4 хранится в поле `birthDate`:

```json
{
  "precision": "range",
  "text": "1940 – 1945",
  "value": "",
  "from": "1940",
  "to": "1945"
}
```

Допустимы точный день, только год, приблизительная дата, диапазон и неизвестная дата.
Старые поля `year` и `datePrecision` читаются при миграции, но в новый файл не записываются.
Ошибочные даты не блокируют открытие проекта: приложение показывает предупреждение, чтобы
пользователь мог исправить запись вручную.

При открытии и сохранении также выполняется мягкая проверка качества семейных данных. Она
предупреждает о возможных дубликатах с совпадающими ФИО и дополнительными признаками, о
циклических родительских связях, рождении ребёнка раньше родителя, слишком маленьком возрасте
для родительства или начала отношений, а также о датах окончания отношений, указанных раньше
их начала. Такие замечания не удаляют записи и не блокируют открытие файла.

### Фотографии

Новая фотография добавляется через карточку человека и сохраняется в `photos` как
встроенный `dataUrl`. Запись содержит `personId`, MIME-тип, размер в байтах и
контрольную сумму. При открытии приложения формат и контрольная сумма проверяются;
повреждённая фотография не блокирует загрузку проекта, но отображается в предупреждениях.

Фотографии из старых файлов, которые указывали на внешний путь, сохраняются как
совместимые внешние ссылки и отмечаются предупреждением: при переносе одного файла
проекта на другой компьютер такой путь может стать недоступным. Чтобы сделать фото
переносимым, его нужно заново выбрать через кнопку «Добавить фото» или «Заменить фото».

## Рабочая копия

Прототип сохраняет последнюю рабочую копию в локальном хранилище браузера. После
изменения человека или добавления родственника срабатывает автоматическая запись с
небольшой задержкой. После перезагрузки приложения рабочая копия восстанавливается
автоматически.

Важно: это хранилище относится к конкретному профилю браузера. Поэтому на этапе
прототипа его нельзя считать полноценной заменой файлу на диске.

## Резервные копии

В браузере хранится до 10 последних снимков. Снимки создаются:

- автоматически после изменения данных;
- после ручного сохранения проекта;
- перед восстановлением другой копии;
- перед открытием нового файла, если есть несохранённые изменения.

Через меню «⋯ → Резервные копии» копию можно скачать отдельным файлом или восстановить.
Перед восстановлением текущие данные также попадают в историю резервных копий.

## Ограничения прототипа

- сохранение проекта сейчас выполняется через загрузку файла браузером;
- файл `.familytree` технически является JSON и пока не защищён от просмотра другими
  программами;
- автоматические копии не дублируются на внешний диск, флешку или в облако;
- постоянное нативное Windows-хранилище пока не заменяет браузерное локальное хранилище;
  встроенные фотографии уже входят в JSON-файл проекта, но внешний путь из старого файла
  не копируется автоматически.

Следующий технический шаг — перенести этот контракт в нативное локальное хранилище и
добавить атомарное сохранение, чтобы сбой во время записи не повреждал рабочий файл.
