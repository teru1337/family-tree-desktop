# Этап P0. Структурная целостность графа связей

## Сделано

- В `storage.js` добавлена отдельная проверка канонической таблицы `relations`.
- Фатальными ошибками файла теперь считаются:
  - неизвестный тип канонической связи;
  - отсутствующий участник связи;
  - связь человека с самим собой;
  - неполная связь или связь не ровно между двумя людьми;
  - повторяющийся идентификатор связи;
  - повторяющаяся семантическая связь;
  - цикл в родительском графе.
- Для партнёрств семантический дубль определяется с учётом пары людей, типа,
  статуса и дат истории. Это позволяет хранить разные исторические союзы, но
  не позволяет дважды записать одну и ту же связь.
- `normalizeProject()` больше не пропускает структурно неверный канонический
  граф молча. Такой файл не восстанавливается поверх рабочего проекта и
  возвращает понятную причину ошибки.
- Миграция версий 1–6 перед строгой проверкой нормализует старые link-ID,
  поэтому прежние файлы с повторно использованными ID не теряют связи.
- Предупреждения переходных массивов старых файлов сохранены: dangling-ссылка
  в legacy-полях не делает старый проект непригодным для открытия.
- В рабочем тестовом сценарии сокращённый проект теперь пересобирается штатной
  функцией, чтобы удаление человека не оставляло каноническую связь на него.
- Общий модуль проверки качества вынесен в отдельный production-chunk, чтобы
  основной renderer-бандл оставался в установленном лимите 500 000 байт.

## Проверка

- Добавлен `stage-45-relation-invariants.test.mjs` с проверками валидного графа,
  orphan/self/cycle/duplicate-связей, строгого открытия и backward compatibility.
- Полный `npm test`: 77 тестов пройдено.
- Версия проекта осталась `0.2.6`; релиз не создавался.

## Границы этапа

Этот этап не меняет формат проекта, UI правой панели, геолокацию, layout и
визуальные линии. Следующий P0-срез должен описать и покрыть атомарные операции
редактирования графа, чтобы UI не мог сформировать противоречивое состояние до
сохранения.
