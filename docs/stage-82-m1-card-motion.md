# Stage 82 M1 — появление и перемещение карточек

Дата: 26.08.2026  
Статус: завершён 26.08.2026.

## Что сделано

- После зафиксированной новой раскладки `TreeCanvas` вычисляет FLIP-дельту
  предыдущей и текущей позиции карточки.
- Перемещение карточек и кнопок сворачивания выполняется через `transform`,
  поэтому геометрия `.familytree`, размеры карточек и канонические связи не
  меняются ради анимации.
- Новые видимые карточки получают отдельный entrance с opacity/scale/translate.
- Для линий рендерятся старая и новая SVG-геометрии: они перекрёстно сменяют
  друг друга, чтобы новая раскладка не появлялась резким скачком.
- Повторная раскладка отменяет предыдущие `requestAnimationFrame` и таймер,
  затем запускает движение от последнего подтверждённого состояния.
- Перетаскивание карточки не перехватывается layout-motion; фокус остаётся на
  прежнем DOM-элементе с тем же `key` и `data-person-id`.
- При `prefers-reduced-motion: reduce` motion-проход пропускается, а новая
  геометрия и фокус остаются доступными.

## Pixso MCP и визуальная база

Локальный Pixso MCP доступен и был проверен на M0. В текущем Pixso-файле всё ещё
нет верхнеуровневого reference frame, поэтому M1 не создаёт внешний макет и не
передаёт туда семейные данные. Визуальная сверка выполняется на реальном
Electron-экране и обезличенной dense-tree fixture из тестов.

- `npm test`: 203/203 теста пройдены.
- `npm run build:renderer`: пройден; основной renderer bundle — 497 513 байт
  из разрешённых 500 000.
- `npm run dist:win`: пройден; создан Windows-пакет из текущего renderer.
- Визуальная проверка текущего renderer выполнена на Windows в Chromium при
  размере 1920×1080: стартовое меню, фоновые линии/карточки и модальное окно
  не обрезаются и не перекрывают основные действия.
- Source-wiring тесты проверяют FLIP-дельту, entrance новых карточек,
  crossfade SVG-связей, отмену предыдущего прохода, стабильные React keys и
  reduced motion.

## Остаточный риск

Проверка движения в автоматических тестах пока покрывает чистую FLIP-математику
и wiring компонентов; полноценный пользовательский сценарий «создать родственника
→ новая раскладка → повторное действие» остаётся частью M2, где появится единая
последовательность карточки, связей и операции добавления.
