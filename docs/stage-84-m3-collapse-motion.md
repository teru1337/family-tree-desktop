# Stage 84 M3 — раскрытие и сворачивание ветвей

Дата: 26.08.2026  
Статус: завершён после проверок этого этапа.

## Что сделано

- Сворачивание остаётся визуальным состоянием `collapsedIds`: канонический
  граф, идентификаторы, порядок связей и формат `.familytree` не меняются.
- `tree-collapse.js` сохраняет корень и активную пару супругов/партнёров, а
  итеративно скрывает потомков пары; независимые ветви остаются видимыми.
- Для раскрытия и сворачивания добавлена отдельная прерываемая motion-сцена:
  FLIP-перемещение, вход возвращаемых карточек и короткий exit новой скрываемой
  группы.
- Предыдущий SVG получает прежний набор скрытых идентификаторов и плавно
  переходит в текущий SVG. Поэтому текущие пути не ведут к скрытым карточкам,
  а старые пути исчезают вместе с exit-сценой.
- Координатор вынесен в `prototype/src/collapse-motion.js`, чтобы сохранить
  запас renderer bundle. Низкоуровневые переходы используют `transform` и
  `opacity`, а отмена старых `requestAnimationFrame`/таймеров защищает от
  устаревшей сцены при быстром повторном действии.
- Кнопка ветви остаётся нативной клавиатурной кнопкой с `aria-label`, фокусом,
  подсказкой и иконками раскрытого/свёрнутого состояния. При
  `prefers-reduced-motion` потомки скрываются без промежуточной анимации, но
  данные, фокус и доступное действие сохраняются.

## Pixso MCP и визуальная база

Локальный Pixso MCP доступен через `http://127.0.0.1:3667/mcp`; handshake и
`tools/list` проходят. В текущем Pixso-файле по-прежнему нет выбранного
верхнеуровневого reference frame, поэтому внешний макет M3 не создавался и
семейные данные туда не передавались. Для этапа использована текущая
production-геометрия и обезличенные regression-сценарии.

## Проверка

- `npm test`: 208/208 тестов пройдены.
- `npm run build:renderer`: пройден; основной JS-бандл — 490 184 из 500 000
  байт, создан также отдельный `collapse-motion` chunk.
- `git diff --check`: пройден.
- Визуально проверен текущий production-renderer в Chromium на Windows при
  1920×1080: стартовое меню, модальное окно и живой декоративный фон не
  обрезаются; обязательный критерий этапа не зависит от запуска установленной
  Windows-сборки.
- Существующие сценарии сохранения, восстановления и повторного открытия
  `.familytree` проходят без изменения формата; новый M3-тест дополнительно
  подтверждает отсутствие мутаций канонического графа при collapse.

## Остаточный риск

Покадровая ручная проверка collapse на реальном пользовательском файле остаётся
отдельным smoke-сценарием: Pixso пока не содержит утверждённого reference board,
а локальная Windows-упаковка может быть заблокирована `EPERM` со стороны
electron-builder. Renderer-проверка и CI-пакетирование остаются достаточными
для закрытия текущего этапа.
