# Инструкция работы по дорожной карте

Этот документ предназначен для дальнейшей работы Codex над
`family-tree-desktop`. Источник согласованных требований —
`docs/remaining-roadmap.md`. Нельзя молча менять принятые решения или порядок
активных приоритетов.

## Порядок выполнения

1. Сначала P0.1: тайм-аут, отмена, ошибки и актуальный адаптер геокодера.
2. Затем P0.2: нативный путь проекта, `Ctrl+S`, резервная копия и атомарная
   запись.
3. Затем P1.1: реальные границы карточек и корректные концы линий.
4. Затем P1.2: маршрутизация подписей, минимальные зазоры и подпись брака.
5. Затем P1.3: обезличенный плотный fixture и геометрические регрессии.
6. Затем P2.1–P2.3: скрытие технических IDs, центрирование стрелки и маска даты.
7. Затем P3.1: масштабирование колесом относительно курсора.
8. В конце P3.2: реестр команд, настройки горячих клавиш, конфликты и
   инструкция.

## Обязательные ограничения

- Не добавлять реальный семейный файл пользователя в Git.
- Не удалять IDs из `.familytree`: скрывать их можно только в UI.
- Не делать интернет обязательным для ручного ввода адреса.
- Не оставлять сетевой запрос без тайм-аута и отмены.
- Не перезаписывать проект напрямую без резервной копии и атомарной записи.
- Не использовать `Win+S` как основной shortcut Windows; использовать `Ctrl+S`.
- Не менять формат проекта без миграции, проверки старых файлов и резервной копии.
- Не исправлять несвязанные функции в рамках этапа.
- Не создавать релиз без отдельного запроса пользователя.

## Проверка каждого этапа

Перед началом определить затронутые модули, данные и критерий готовности.
После изменения выполнить соответствующие тесты, `npm test`,
`npm run build:renderer`, `git diff --check` и ручную визуальную проверку.
Следить за лимитом renderer bundle: не превышать 500 000 байт.

Для изменений хранения дополнительно проверять миграцию, резервную копию,
атомарное сохранение, повторное открытие и восстановление. Для полотна — обычный
и крупный текст, разные ширины панели, полное дерево, родственную ветвь,
экспорт и реальный локальный файл. Для горячих клавиш — фокус в полях,
модальные окна, конфликт сочетаний и старые проекты без настроек shortcuts.

Каждый завершённый этап должен иметь отдельный `docs/stage-*.md`, commit и push.
В отчёте фиксировать сделанное, тесты, ограничения и оставшиеся риски.

## Правила против отклонения от плана

- Если проблема относится к нескольким слоям, сначала исправлять модель данных и
  контракт, затем UI.
- Не скрывать дефект визуальным обходом, если он вызван неправильной геометрией
  или асинхронным состоянием.
- Не считать зелёную сборку доказательством корректности: нужны сценарии,
  повторное открытие и визуальная проверка.
- Если обнаружена новая неоднозначность, остановить только затронутый подэтап,
  описать факт, предположение и недостающий выбор пользователя.
- После каждого этапа сверять результат с активным блоком P0–P3 и не переходить к
  следующему при невыполненном критерии готовности.
