# Модель данных v1

## 1. Цель

Модель должна хранить семейное дерево локально и не требовать полного набора
сведений о каждом человеке. Любое поле, кроме технического идентификатора,
может отсутствовать.

В первой версии поддерживаются:

- ФИО и варианты имени, включая девичью фамилию;
- дата и место рождения;
- профессия и краткая биография;
- фотографии;
- биологические, усыновительские, отчимские и опекунские связи;
- несколько браков или партнёрств, разводы и другие причины окончания связи;
- приблизительные, неполные и неизвестные даты.

Не входят в модель первой версии как обязательные функции: источники,
документы, неродственные контакты, облачная синхронизация, шифрование и
совместное редактирование.

## 2. Основные сущности

### ProjectMetadata — проект

Содержит техническую информацию о семейном проекте:

- уникальный идентификатор проекта;
- название проекта;
- версию схемы данных;
- дату создания и последнего изменения;
- настройки отображения и экспорта.

### Person — человек

Содержит:

- стабильный уникальный идентификатор;
- варианты имени;
- профессию;
- краткую биографию;
- общую заметку;
- дату создания и изменения записи;
- признак архивирования записи, если позже понадобится безопасное скрытие вместо удаления.

Поле пола в v1 не добавляется: для построения связей оно не требуется, а
подписи «родитель», «супруг» и «ребёнок» не зависят от пола.

### PersonName — вариант имени

Один человек может иметь несколько вариантов имени:

- основное имя;
- девичья фамилия;
- альтернативное или историческое написание.

Каждый вариант состоит из необязательных частей:

- фамилия;
- имя;
- отчество;
- отображаемая строка в исходном виде.

Хранение исходной строки важно для старых или нестандартно записанных имён.

### DateValue — дата

Дата хранится не одной строкой, а с указанием точности:

| Тип | Пример | Хранение |
|---|---|---|
| `exact` | 12.04.1950 | начало и конец совпадают |
| `month` | апрель 1950 | интервал внутри месяца |
| `year` | 1950 год | интервал от начала до конца года |
| `approximate` | около 1950 | известный ориентир или интервал |
| `before` | до 1950 | известна верхняя граница |
| `after` | после 1950 | известна нижняя граница |
| `range` | 1949–1951 | начало и конец интервала |
| `unknown` | неизвестно | числовых значений нет |

Дополнительно сохраняются:

- исходный текст, введённый пользователем;
- календарь, по умолчанию григорианский.

Дата не должна преобразовываться в точную, если пользователь указал только
год или приблизительное значение.

### PersonEvent — событие человека

В v1 используется прежде всего для рождения:

- тип события: `birth`;
- дата с указанной точностью;
- место;
- необязательная заметка.

Структура допускает будущие события, например смерть или переезд, но их
расширенный интерфейс не является частью первой версии.

### Place — место

Для первой версии достаточно сохранять место рождения как свободный текст.
Дополнительно можно хранить отдельные необязательные части:

- населённый пункт;
- район или область;
- страна.

Исходная строка места сохраняется всегда, чтобы не потерять историческое или
неоднозначное написание.

### ParentLink — родительская связь

Связывает одного родителя с одним ребёнком:

- `biological` — биологическая связь;
- `adoptive` — усыновление или удочерение;
- `step` — отчим или мачеха;
- `guardian` — опекун;
- `unknown` — тип связи неизвестен.

Отдельная запись на каждого родителя позволяет хранить одного родителя,
неполные сведения и разные типы связи одновременно.

### Partnership — супружеская или партнёрская связь

Связывает двух людей и поддерживает несколько связей у одного человека:

- `marriage` — брак;
- `partnership` — партнёрство;
- `unknown` — тип неизвестен.

Для связи могут быть указаны:

- дата начала;
- дата окончания;
- причина окончания: развод, раздельное проживание, смерть партнёра или неизвестная причина;
- заметка.

Пол и роли участников не фиксируются, поэтому модель допускает любые пары и
не делает предположений по имени.

### Photo — фотография

Фотография принадлежит человеку и содержит:

- уникальный идентификатор;
- относительный путь внутри файла проекта;
- исходное имя файла;
- тип файла;
- подпись;
- необязательную дату;
- признак основной фотографии;
- порядок отображения.

Сами изображения не встраиваются в таблицу базы данных: они хранятся в
каталоге `media` внутри файла проекта. Это упрощает резервное копирование и
экспорт.

## 3. Логическая структура проекта

Пользовательский файл проекта планируется как контейнер с расширением
`.familytree`:

```text
family-tree.familytree
├── manifest.json       # версия формата и контрольная информация
├── data.sqlite         # структурированные данные
└── media/              # фотографии с относительными именами
```

Приложение должно сохранять файл атомарно: сначала записывать временную копию,
проверять её, затем заменять основной файл. Это снижает риск повреждения при
сбое питания или закрытии приложения.

## 4. Правила целостности

1. У каждой записи есть стабильный UUID.
2. Пустые значения хранятся как `NULL`, а не как текст `Неизвестно`.
3. Человек не может быть родителем самого себя.
4. Человек не может быть связан партнёрством сам с собой.
5. Один и тот же вариант родительской связи не должен дублироваться.
6. Порядок участников партнёрства нормализуется, чтобы связь A–B не дублировалась связью B–A.
7. У человека может быть много вариантов имени, но только один основной.
8. У человека может быть много фотографий, но только одна основная.
9. Удаление человека должно требовать подтверждения и заранее создавать резервную копию.
10. При удалении проекта изображения и записи должны удаляться только вместе с явно выбранным пользователем проектом.

## 5. Решения для интерфейса

- Все поля в форме человека необязательны.
- Неизвестная дата выбирается явно, а не вводится пустым текстом.
- Для приблизительной даты показываются понятные варианты: «около», «до», «после», «между».
- Основное имя можно собрать автоматически из заполненных частей, но пользователь может сохранить собственное отображаемое написание.
- Связи добавляются через понятные действия: «Добавить родителя», «Добавить ребёнка», «Добавить супруга/партнёра».
- Перед удалением показывается, какие связанные записи будут затронуты.

- внешний вид карточки человека;

- правила показа фотографий на узлах дерева;
- поведение при конфликтующих или циклических связях;
- набор стилей дерева и параметры большого экспорта.
